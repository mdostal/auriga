Auriga routes the swarm.

A swarm of agents building software needs one thing deciding who does what and when. Auriga senses Multica board state and dispatches each unit of work to the right lane and agent — pure, deterministic, unit-tested decisions; zero destructive actions.

What & why

The decision layer between the board and the swarm

Without a router, tickets pile up unassigned, hive-authored stories get routed to runtimes that can't run them, and a single overloaded runtime collapses throughput to zero. Auriga runs as a standalone service — its own repo, its own process — so routing policy can evolve, be tested, and be swapped independently of the agents it dispatches to.

Capability-aware

Detects hive-authored stories (by label or the methodology/steps shape Minerva emits) and forces them onto Claude+plugin-hive lanes — Codex/Opencode lanes can't run them.

Capacity-disciplined

Per-agent, per-runtime, and per-cycle caps mean the router never mass-flips the board or collapses a shared runtime under contention.

Safe by construction

Only ever assigns and re-runs; never deletes or cancels. Board-fact-driven state transitions — a run finishing is never confused with a PR merging.

Architecture

Scan → decide → dispatch

Every cycle: scan configured Multica projects → recover zombies → advance issue status from board facts alone → size and fire a review squad for anything in review → select a small batch of unassigned todos → route by capability and project lane → assign and verify → log → sleep. See docs/ARCHITECTURE.md for the full breakdown.

Role in Pantheon

One god among many

Auriga is one plugin god bound into the pantheon-v2 host — every god owns its own repo. It routes work across the Multica board and dispatches hive-authored stories to lanes running plugin-hive.

Minerva — planning Heimdall — lane gateway / token routing Hellsing — zombie/worker reaping Consus — ideation → sign-off Argus — observability
Quickstart

Run it locally

The live router lives in src/router/ (Node 24+, no dependencies).

git clone git@github.com:mdostal/auriga.git
cd auriga/src/router

npm test           # run the pure-logic unit suite (node --test)

npm run dry        # one cycle, compute + log decisions, assign NOTHING
npm run once       # one real cycle then exit

# supervised: keep exactly ONE detached router alive, restart on death
nohup ./supervisor.sh >> /tmp/auriga-supervisor.log 2>&1 &
